# ADR-010：规则扩充与合同级评测基线

- 状态：已接受
- 日期：2026-10-27
- 决策人：用户 + Trae AI

## 背景

2026-10-27 用户新增一批模拟合同（放入 `data/knowledge/`），要求“查收后继续下一步”。查收结果：

- 实际为 **6 个 Markdown 文件、共 50 份合同（C01–C50）**，不是用户所说的 60 份；未发现 C51–C60；
- 每份合同自带一张「条款—问题映射摘要」（条款 → Q 编号 → 期望召回 → 干扰项），属于**检索期望**，不是规则判级 gold；
- 合同大量使用 `[C] 天`、`[X]` 等占位符，数值型规则无法通用判定。

首轮评测（修正 `R-TRD-001` 的 `®` 正则缺陷后）暴露出两个事实：

1. **规则覆盖严重不足**：50 份合同里 45 份“全部 pass”，只有 5 份命中 `R-PAY-002`；
2. **既有规则存在真实误报**：`Incoterms® 2020` 的注册商标符号导致 `R-TRD-001` 在 40 份合同上误报“未约定版本”。

如果不扩充规则，第四阶段的评测只能证明“规则几乎不触发”，既无法支撑答辩，也无法证明“规则唯一判级”这条硬约束在实践中有效。

## 选项

- **A. 用 LLM 做风险判级，补足规则覆盖**：违反硬约束（等级只能来自 Python），不可选。
- **B. 维持 7 条规则，只做评测**：诚实但结论是“45/50 无风险”，与合同自带的映射摘要明显矛盾，评测价值低。
- **C. 只用确定性 DSL 扩充规则，且每条规则必须先在语料上给出可复现的命中集合**：选中。
- **D. 把「条款—问题映射摘要」直接当规则 gold**：不可行。它是检索期望（如“CISG 第 39(2) 条两年期限”），并不标注 `red/yellow/pass`；直接当 gold 会把检索评测与规则评测混为一谈。

## 决策

### 1. 规则集扩到 13 条（新增 6 条，全部为确定性文本规则）

| rule_id | 主题 | 等级 | 语料命中 | 判定依据 |
|---|---|---|---|---|
| `R-DIS-003` | 仲裁与诉讼并列（“或裁或审”） | red | C47 | 同一句内“仲裁 … 或/或者 … 法院/诉讼” |
| `R-DIS-004` | 仲裁裁决后仍可向法院起诉（“先裁后审”） | red | C48 | “仲裁裁决 … 后 … 法院/诉讼” |
| `R-INS-001` | CIF/CIP 约定了投保但未写保额/比例 | yellow | C04 | CIF/CIP + 保险表述 + 无“保额 … %/合同价” |
| `R-INC-001` | 贸易术语与运费承担相互矛盾 | yellow | C11 | FOB/EXW/FCA … 运费由卖方预付/承担 |
| `R-INC-002` | FOB/EXW 用于整箱集装箱货物 | yellow | C23 | FOB/EXW … 集装箱/FCL/堆场 |
| `R-INP-002` | 检验或通知期限以小时计（极短） | yellow | C09 | “N 小时 … 检验/通知/异议” |

### 2. 新规则的准入四关（后续扩充沿用）

1. **可确定性表达**：只能用 `app/rules/dsl.py` 的白名单条件（关键词/正则/字段/数值/日期/布尔组合），不用 `eval`、不引入语义判断；
2. **正反 fixture**：`tests/test_rules.py` 里每条规则至少一组“命中文本”和一组“不应命中的近似文本”，并校验证据 span 可在原文切片回填；
3. **语料命中集合可复现**：在 `data/contracts/` 的 50 份合同上跑出的命中集合必须精确等于预期（当前 6 条规则各命中 1 份），并固化为 `EXPECTED_CORPUS_HITS` 回归测试；
4. **样例合同零误报**：`data/samples/` 的两份样例（含风险的 FOB 件、干净 CIF 件）不得命中新规则，避免破坏既有端到端断言。

任何一条不满足就不并入规则集，宁可少一条，也不把“看起来像风险”的启发式塞进判级。

### 3. 有意为之的“不触发”

`R-INS-001` **只在合同确实约定了投保、但没写保额/比例时触发**；对“CIF 但完全没写保险条款”的合同（C09/C15/C40、干净样例）不触发。原因：Incoterms® 2020 的 CIF/CIP 默认规则已经补位（合同价 110%、最低 ICC(C)），缺省不等于缺陷；把“没写保险”一律判黄会在专业合同上产生大量噪声。C04 的映射摘要也明确“默认规则补充”，真正的问题是“一切险”措辞与默认险别的差异。

### 4. 模拟合同的数据归属

- 原始文件 `data/knowledge/模拟合同1..6.md` **保持不动**，不写入 `manifest.yaml`（它们不是法规知识，不参与 RAG 引用白名单）；
- 由 `eval/prepare_contracts.py` 拆分为单份合同 `data/contracts/C01.md … C50.md`（生成物，可重建）；
- 由同一脚本把映射摘要解析为 `data/eval/gold_contracts.json`（50 份 / 105 条“条款 → Q 编号 → 期望召回 → 干扰项”）；
- 规则级评测由 `eval/run_eval.py` 执行，全部 Python 规则 + 解析/切分，**不调用 LLM、不需要 Key**，结果落 `eval/results/rules-YYYYMMDD.json`。

### 5. 评测口径（当前只报“触发情况”，不报准确率）

结果文件包含 `rule_count / contract_count / contracts_with_hits / level_counts / hit_counts / contracts_without_hits`，并显式写明“未命中不等于无风险”。**在规则级 gold（`合同 × rule_id → red/yellow/pass`）建立前，不计算 precision/recall/F1，不在 README 或答辩中宣称准确率。**

## 后果

- **正面**：规则 7 → 13 条；50 份合同上从“45 份全 pass”变为“11 份命中（2 red / 9 yellow），39 份无命中”，每个新规则命中集合精确可复现；评测链路（拆合同 → gold → 跑评测 → 结果文件）可一键重跑。
- **代价 / 风险**：
  - 6 条新规则是在**同一批 50 份合同上设计并验证**的，属于“同分布验证”，不能据此宣称泛化精度；后续需留出独立合同集（新 ISSUE-020 记录）；
  - 规则仍是关键词/正则级，改写措辞（英文条款、不同表达）会漏检；`R-INC-001` 允许跨句 160 字符，长条款可能跨条匹配，需人工核对证据；
  - 39/50 完全未命中，说明覆盖仍不足（不可抗力、责任上限、质保期、所有权保留、合规等尚未做），ISSUE-009 保持 OPEN；
  - 模拟合同自带映射摘要是检索级期望，ISSUE-005/018 的“规则级 gold”与“检索评测映射”仍未完成。
- **后续需要补的测试/文档**：独立合同集的留出验证；规则级 gold 标注；`R-INS-001` 英文保险措辞样例；`eval/` 命令写入 README 与交接文档。
