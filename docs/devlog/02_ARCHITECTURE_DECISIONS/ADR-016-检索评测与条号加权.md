# ADR-016：检索评测（100 题 gold 映射）与“点名条号/来源”加权

- 状态：**已接受（2026-10-28）**
- 日期：2026-10-28
- 决策人：用户（要求先做检索评测）+ Trae AI
- 关联：ADR-008（RAG MVP）、ADR-011（评测方法、报数纪律）、ISSUE-018（检索评测缺 gold 映射）

## 1. 背景

ADR-008 落地的是本地 BM25 检索，但一直**没有指标**：`data/knowledge/100问题.md` 里写的是
概念标签（`CISG-25` / `INC-CIF A5` / `JI-CC-1`），而检索返回的是
`source_id#section`（`CISG-ZH#s27` / `INCOTERMS-2020#s12` / `SPC-CONTRACT-2023#第一条`）。
两套名字对不上，所以 ISSUE-018 一直挂着：能跑，但报不出召回率，也无法判断改检索是否有效。

同时评测第一次跑出来就暴露了真实缺陷：

| 口径 | R@1 | R@3 | R@5 | MRR |
|---|---|---|---|---|
| lenient（条文原文 + `CISG-KEY` 解读稿） | 0.516 | 0.800 | 0.874 | 0.667 |
| strict（仅条文原文） | 0.158 | 0.390 | 0.537 | 0.290 |

`strict R@1` 只有 0.16 的根因不是“词法检索不行”，而是**提问里已经写明了条号**（第 584 条、
CISG 第 39(2) 条），但 BM25 仍按词频排序，让解读稿或相邻条文压过被点名的条文。

## 2. 选项

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 人工逐题标 citation | 最权威 | 95 题 × 3 来源，人工成本高，且语料一改就过期 | 不选（不可持续） |
| B. 规则映射 + 通用条号解析（标签 → 语料） | 可复现、可 diff、随语料自动重建 | 只覆盖“条号可解析”的题；语料缺口需显式登记 | **采用** |
| C. 引入向量检索提升语义召回 | 同义改写召回好 | 违反“无向量库/无 embedding”的硬约束；不可解释 | 不选（本阶段） |
| D. 检索时用 LLM 改写成条号 | 对自然语言更稳 | 每次检索多一次模型调用，离线/无 Key 不可用 | 不选（可用工具层承载） |
| E. 提问点名条号时给该条文加权 | 零成本、确定、可测；直击 0.16 的主因 | 只解决“点条号”的题型 | **采用（先做）** |

## 3. 决策

### 3.1 gold 构造（`eval/rag_gold.py` + `data/eval/rag_label_map.yaml`）

- **两层**：`labels` 登记需要人工判断的主题标签（Incoterms 整理稿无 A/B 编号、风险红线未按编号组织）；
  `CISG-N` / `CC-N` / `LAW-N` / `JI-CC-N` 由通用规则解析成 `第{中文数字}条`。
- **一个标签 → 多条可接受片段**：CISG 同时认中文原文（`CISG-ZH`）、英文原文（`CISG-EN`）、
  权威解读（`CISG-KEY`）；命中任一即算召回。
- **语料缺口显式登记**（`gaps`）：某标签在语料里确实没有对应文本时，该题**不进召回率分母**，
  单独报“语料未覆盖”，绝不把语料缺口算成检索失败。
- 生成物 `data/eval/gold_rag.json` 可 diff；`tests/test_rag_eval.py` 里有一条回归守卫，
  语料或题目一改就失败，提示重建 gold。
- 中英文条号转换只在 `app/services/chinese_numbers.py` 实现一份（`第584条 ↔ 第五百八十四条`），
  检索加权与 gold 构造共用，避免“评测命中但线上不命中”。

### 3.2 评测口径（`eval/run_rag_eval.py`）

- 两套同时报，禁止混读：
  - `ranking`：`top_k=5`、不过阈值，看**排序能力**；
  - `production`：`RAG_TOP_K` / `RAG_MIN_SCORE` 的实际配置，看**线上会不会返回空**。
- 两个指标口径：`lenient`（条文原文或解读稿都算）与 `strict`（只认条文原文）。
  只报 lenient 会把“命中解读稿”当成“命中条文”，必须两个一起看。
- 95 题可评测 / 5 题语料未覆盖；分组（CISG / Incoterms / 冲突法 / 民法典 / 交叉）各报 R@k。
- 结果落 `eval/results/rag-<日期>.json`，含每题期望、实返 citation 与排名；报数时必须带
  样本数 + 语料 + 日期 + 命令（ADR-011 的纪律）。

### 3.3 检索加权（`app/services/rag.py`）

- 只做**排序加权**，不过滤片段、不新增片段、不改判级：
  - 提问出现 `第N条`（含 `第39(2)条` 这类款项写法）→ 标题为 `第N条` / `第{中文}条` /
    `第N条｜…` / `Article N` 的片段 ×2.5，其中条文原文再 ×1.1（避免解读稿压过原文）；
  - 提问出现法律名（民法典 / 法律适用法 / 合同编通则 / Incoterms 术语 / CISG / UCP600 …）→
    该来源 ×1.15；
  - 没有线索时加权全为 1.0，行为与原 BM25 **完全一致**（有测试钉住）。
- 语料缺口与同义词问题显式留白：`_article_numbers` 抽不出条号时不做猜测。

## 4. 结果（2026-10-28，同一语料、同一命令）

```powershell
python -m eval.rag_gold --write      # 重建 gold
python -m eval.run_rag_eval          # 出指标
```

| 口径 | 指标 | 加权前 | 加权后 |
|---|---|---|---|
| lenient | R@1 | 0.516 | **0.747** |
| lenient | R@3 | 0.800 | **0.958** |
| lenient | R@5 | 0.874 | **0.979** |
| lenient | MRR | 0.667 | **0.849** |
| strict | R@1 | 0.158 | **0.305** |
| strict | R@3 | 0.390 | **0.758** |
| strict | R@5 | 0.537 | **0.821** |
| strict | MRR | 0.290 | **0.524** |

剩余 4 道题（#4 / #6 / #43 / #100）不在前 3：都是**提问里没写条号、靠语义指代**的题
（“单一质量指标不符但货物仍可转售”“集装箱场景下使用 FOB”）。这类需要语义检索或查询改写，
属于下一阶段的已知边界，不做“对着这 4 题调参”。

## 5. 后果

- 正向：RAG 第一次有了可复现指标；检索改动有了对照基线；`strict` 口径逼着“引用条文原文”
  而不是只引解读稿。
- 代价：`labels` 里的人工映射需要随语料维护（新增文档要登记匹配器）；
  加权常量（2.5 / 1.15 / 1.1）是经验值，只能通过重跑评测调整，不许手改到“刚好过”。
- 边界：加权只对“点条号 / 点法律名”的题型有效；同义改写、跨语言提问仍靠 BM25，
  已知不足记在 ISSUE-018 的备注与 ISSUE-033。
