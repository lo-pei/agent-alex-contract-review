# ADR-005：文档解析与证据模型

- 状态：**已接受（2026-10-26，用户确认「ADR 确认，开始第三阶段」）**
- 日期：2026-10-26
- 决策人：用户 + Trae AI
- 关联：ADR-003；`01_RESEARCH_LOG.md` 模式 C；`开发提示词.md` 第 134 行
- 影响范围：`app/nodes/ingest.py`、`app/nodes/segment.py`、`app/services/evidence.py`、`app/schemas.py`、报告与 UI 高亮

---

## 1. 背景

报告中的每条风险都要能回指原文，否则“可解释”只是口号。需要同时解决：

- PDF / DOCX / TXT 的文本提取；
- 分页与全局字符偏移；
- 条款切分但保留原文位置；
- LLM 抽取/解释的引文核验；
- 扫描件、表格、复杂版式的边界；
- 不引入许可证有风险的默认依赖。

调研结论：laolaola 的 `文件名:第N页:字符start-end` 成本低、展示直观；Harvey 的精确定位（只允许 Unicode/空白规范化，不做模糊匹配）能有效拦截幻觉引文。

---

## 2. 可选方案

### 2.1 解析库

| 方案 | 优点 | 缺点 | 许可证 |
|---|---|---|---|
| `pypdf` | 纯 Python、轻量、文本型 PDF 足够；无系统依赖 | 复杂版式/表格弱；扫描件无文本 | BSD |
| `PyMuPDF` | 文本/坐标/表格能力强；速度快 | AGPL/商业双许可；默认引入有合规风险 | AGPL / commercial |
| `pdfplumber` | 表格能力强；基于 pdfminer | 速度较慢；依赖更多；MVP 不一定需要 | MIT |
| 系统 OCR（Tesseract 等） | 支持扫描件 | 额外安装、语言包、质量不稳定；10 天 MVP 过重 | 多种 |

### 2.2 位置模型

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 只存条款文本 | 简单 | 无法回指页码/偏移；报告不可追溯 |
| B. 存 PDF 原始字节偏移 | 最精确 | PDF 文本层与字节偏移映射复杂；跨库不稳定 |
| C. 规范文本 + 页偏移 + 全局字符偏移 | 统一三种格式；可实现高亮与 citation | 偏移是“规范化后文本”的偏移，不是原始字节；需在文档中说明 |
| D. 存每页独立偏移，不做全局 | 简单 | 跨页引用/全局定位困难；条款切分跨页麻烦 |

### 2.3 条款切分

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. LLM 切分 | 语义好 | 不确定、不可回归；偏移不可靠；成本高 |
| B. 纯正则标题切分 | 确定、快、可测试 | 复杂版式/无标题合同效果差；需要 fallback |
| C. 正则 + 段落 fallback | 兼顾确定性与覆盖率 | 需要处理小段落合并、最大长度、覆盖完整性 |
| D. 固定窗口 | 简单 | 切断条款语义；报告可读性差 |

---

## 3. 决策

**采用：`pypdf` + `python-docx` + TXT/Markdown；规范文本 + 页偏移 + 全局字符偏移；正则标题切分 + 段落 fallback。**

### 3.1 支持范围

| 格式 | 支持 | 说明 |
|---|---|---|
| `.pdf`（文本型） | ✅ | 按页提取；扫描件不支持 |
| `.docx` | ✅ | 段落 + 表格文本；无真实分页，统一记为 `p1` |
| `.txt` / `.md` | ✅ | UTF-8 / GB18030 / Latin-1 依次尝试 |
| `.doc`（旧版） | ❌ | 明确提示“请另存为 .docx” |
| 扫描 PDF / 图片 | ❌ | 明确提示“未检测到文本层，请提供可复制文本的 PDF 或 DOCX” |
| 加密 PDF | ❌（除非空密码可解密） | 明确提示 |
| 超过 15 MB / 200k 字符 / 200 页 | ❌ | 返回可读错误，不进入图 |

### 3.2 规范文本（canonical text）

```python
class Page(BaseModel):
    page_number: int  # 从 1 开始；DOCX/TXT 固定为 1
    text: str
    start_offset: int  # 在 canonical_text 中的全局起点
    end_offset: int  # 全局终点（不含）


class ParsedDocument(BaseModel):
    filename: str  # 仅 basename，已做路径安全处理
    media_type: Literal["pdf", "docx", "text"]
    pages: list[Page]
    text: str  # canonical_text
    sha256: str
    warnings: list[str]
```

构建规则：

1. 解码后统一换行：`\r\n` / `\r` → `\n`；
2. 每页 `text` 做最小清理：去掉 `\x00`，保留段落换行；不做大规模空白重排（避免偏移错位）；
3. `canonical_text = "\n\n".join(page.text for page in pages)`；
4. `page.start_offset = 已拼接长度`；`page.end_offset = start + len(page.text)`；
5. **所有 `start/end` 都是 canonical_text 的字符索引**，不是原始 PDF 字节偏移，也不是页内偏移；
6. 页间分隔符不属于任何页；定位到分隔符时归入前一页；
7. `sha256` 对原始文件字节计算，用于去重/审计，不用于定位。

> UI 高亮时使用 `canonical_text[start:end]`；如果展示的是分页视图，按 `page.start_offset` 换算页内位置。

### 3.3 解析流程

```text
ingest_document(file_path)
  ├─ 校验扩展名/大小/MIME（尽量）
  ├─ .pdf  → pypdf.PdfReader
  │    ├─ is_encrypted → 尝试空密码；失败 → 明确错误
  │    ├─ 逐页 extract_text()
  │    ├─ 总文本 < 50 字符且页数 > 0 → 判定为扫描件/无文本层 → 错误
  │    └─ 组装 pages/canonical_text
  ├─ .docx → python-docx
  │    ├─ 按文档顺序读取段落与表格（表格按行拼成文本）
  │    ├─ 合并为单页 p1（DOCX 无固定分页）
  │    └─ 忽略页眉/页脚（MVP）
  ├─ .txt/.md → bytes → 依次尝试 utf-8-sig / gb18030 / latin-1
  │    └─ 单页 p1
  └─ 空文本/超过上限 → 明确错误
```

- PDF 表格/多栏：pypdf 可能打乱列顺序；在 `warnings` 中提示“复杂版式可能需要人工核对”，不假装解析完美；
- DOCX 表格：按行拼接，单元格用 ` | ` 分隔；保留段落顺序（通过 XML body 迭代，而不是先段落再表格）；
- 文件名只保留 basename，禁止 `..`、路径分隔符、控制字符；报告不暴露服务器绝对路径。

### 3.4 条款模型

```python
class Clause(BaseModel):
    clause_id: str  # C000 前言；C001... 正文
    title: str
    text: str  # 含标题的完整原文片段
    page: int  # 起始页
    start: int  # canonical_text 全局起点
    end: int  # 全局终点（不含）
    clause_type: str | None  # 确定性关键词分类，可为 None
```

#### 切分算法（确定性）

1. **标题识别**：逐行扫描，匹配以下模式且行长 ≤ 120：
   - 中文：`^第[一二三四五六七八九十百零〇\d]+条`、`^[一二三四五六七八九十]+、`、`^（[一二三四五六七八九十]+）`、`^\d+(\.\d+)*[、.．\s]`
   - 英文：`^(ARTICLE|Article|SECTION|Section|CLAUSE|Clause)\s+[0-9IVXLC]+`
   - 标题行本身可以后跟标题文字；不要求全大写。
2. **切分**：第一个标题前 → `C000`（前言，若为空则跳过）；每个标题到下一个标题前 → 一个条款；`text` 包含标题行。
3. **小条款合并**：如果相邻片段 < 80 字符，合并到前一条款（前言除外），避免“只有标题没有内容”。
4. **超长条款拆分**：单条款 > 4000 字符时，按 `\n\n` 段落 / 句号 / 分号拆分；每段仍保留正确的全局偏移；`clause_id` 追加 `-1/-2`（如 `C003-1`）。
5. **无标题 fallback**：按空行段落聚合，目标 300–2000 字符；单段 > 4000 按句子拆；确保 `start/end` 连续覆盖正文，不重叠。
6. **最大条款数** 200；超过则报错（提示拆分合同或提高上限）。
7. `clause_type` 由确定性关键词表给出（`payment/delivery/inspection/warranty/liability/dispute/force_majeure/preamble/general`），**不调用 LLM**；仅用于展示/分组，不用于规则唯一判级。

> 条款切分是纯函数，输入 `ParsedDocument`，输出 `Clause[]`；必须用固定 fixture 做快照测试。

### 3.5 证据定位（`locate_quote`）

```python
class Evidence(BaseModel):
    quote: str
    start: int | None
    end: int | None
    page: int | None
    clause_id: str | None
    grounded: bool
```

算法：

1. 输入 `quote` 先去掉首尾空白（记录 trim 偏移），空字符串直接失败；
2. 最短长度：`min(8, len(clause.text))`；太短不允许作为证据（避免“甲方”这种无意义片段）；
3. **精确匹配**：`canonical_text.find(quote, clause.start, clause.end)`；
4. **规范化匹配**（精确失败时）：
   - 仅做 Unicode NFC 与连续空白折叠为单个空格；
   - 建立“规范化字符 → 原文字符索引”映射；
   - 在规范化文本中查找，再映射回原文 `start/end`；
   - **禁止**：模糊相似度、标点删除、数字转写、否定词删除、大小写重写后不回映；
5. 仍失败 → `grounded=false`，`start/end/page=null`；
6. `page` 由全局 `start` 用 `bisect` 在 `pages.start_offset` 中查找；
7. `clause_id` 由全局 `start` 在 `clauses` 中查找；若落在分隔符/间隙，取前一个覆盖的条款；
8. citation：
   ```text
   sales_contract.pdf:p2:1834-1902
   ```
   - 无定位：`无原文证据`；
   - 跨页：用起始页，并在报告标注“跨页引用”。

调用方：

- 规则文本命中：用命中片段作为 quote 定位；
- LLM 抽取字段：`quote` 必须定位成功，否则字段置 null + `to_verify`；
- LLM 解释：`quote` 必须定位成功，否则丢弃解释、规则理由兜底（ADR-003）。

### 3.6 规则与证据的协作

- 规则引擎的文本规则在 `canonical_text` 上匹配（不区分大小写），命中后调用 `locate_quote` 回填 `Evidence`；
- 字段规则使用 `ContractFacts` 的值；其证据来自字段抽取时的 quote（已核验）；
- 同一条规则多个命中：保留最多 5 条证据，按出现顺序；报告可折叠；
- 去重：同 `rule_id` + 同 `clause_id` + 同 `quote` 只保留一条；不同条款的相同话术保留（可能是重复条款风险）。

### 3.7 错误与降级

| 情况 | 行为 |
|---|---|
| 不支持格式/旧版 .doc | 进入图前返回 400/415，明确提示 |
| 空文件/全空白 | 400，提示“合同内容为空” |
| 扫描 PDF（无文本层） | 400/422，提示“未检测到文本层，请提供可复制文本的 PDF 或 DOCX” |
| 加密 PDF 无法解密 | 400/422，提示“请移除密码后上传” |
| 页数/字符数超限 | 400，提示上限 |
| 某页提取为空 | 保留空页，`warnings` 记录；若全文仍可用则继续 |
| 表格/多栏错乱 | `warnings` 记录“复杂版式，建议人工核对”，不阻断 |
| DOCX 无分页 | 统一 `p1`；citation 页码意义有限，报告中说明 |
| TXT 编码无法识别 | 明确错误，提示另存为 UTF-8 |
| 条款切分不到任何标题 | 段落 fallback；若仍失败（全文 < 80 字符）→ 单条款 `C001` |
| 条款数 > 200 | 报错，建议拆分合同或提高上限 |

### 3.8 安全与隐私

- 解析在本地进程内完成，不上传第三方；
- 不使用 `eval`、不执行宏、不解析外部链接；
- PDF/DOCX 解析设置大小/页数/字符上限，避免压缩炸弹/超大文件拖垮进程；
- 报告/日志不打印完整合同；只打印 `filename`（basename）、`sha256` 前缀、页数、字符数；
- UI 展示原文时做 HTML 转义，避免合同中的 `<script>` 等被渲染；
- `.data/` 与上传临时文件加入 `.gitignore`，评审结束清理。

## 4. 被否决方案及原因

| 方案 | 否决原因 |
|---|---|
| PyMuPDF 作为默认依赖 | AGPL/商业双许可；比赛项目不应引入许可证不确定性 |
| pdfplumber 作为默认依赖 | 依赖更多、速度慢；MVP 的合同以文本型 PDF/DOCX 为主 |
| OCR（Tesseract） | 额外安装、语言包、质量不稳定；10 天 MVP 不做 |
| LLM 切分条款 | 不确定、不可回归、偏移不可靠；违反“规则/确定性优先” |
| 只存条款文本 | 无法回指页码/字符偏移；报告不可追溯 |
| 存 PDF 原始字节偏移 | 跨库映射复杂、不稳定；维护成本高 |
| 固定窗口切分 | 切断条款语义；报告可读性差 |
| 对引文做模糊匹配 | 会把“近似”当“原文”，制造幻觉证据；Harvey 的反例正是禁止模糊匹配 |
| DOCX 强行分页 | DOCX 没有固定分页；伪造页码会误导；统一 p1 + 说明更诚实 |

## 5. 后果

### 正面

- 三种格式统一为 canonical text，规则/抽取/解释/报告共用一套偏移；
- 每条风险可展示 `文件名:p页:start-end`，UI 可高亮；
- 引文核验严格，LLM 幻觉引文会被拦截；
- 解析失败有明确错误，不会把扫描件当“无风险合同”。

### 代价与风险

- 偏移是规范化文本偏移，不是原始 PDF 字节；报告中需注明；
- pypdf 对复杂表格/多栏合同可能错乱；只能 warning + 人工核对；
- DOCX 无真实页码；citation 的页信息有限；
- 条款切分依赖标题格式；无标题合同用段落 fallback，可能切得不理想；
- 200k 字符/200 页上限可能拒绝超长合同；MVP 接受；
- NFC/空白规范化需要仔细实现索引映射，测试必须覆盖多空白、跨页、找不到三种情况。

### 对后续模块的影响

- 报告/UI 必须使用 canonical text 做高亮，不能直接用原始 PDF 渲染；
- 规则引擎的文本匹配与证据定位共享 `canonical_text`；
- 评测 fixture 需要固定 canonical text 与期望偏移，避免因解析库升级导致偏移漂移；
- 若后续引入 pdfplumber/OCR，需要新增 ADR，并保持 `Evidence` 接口不变。
