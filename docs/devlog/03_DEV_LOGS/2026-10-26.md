### 8.3 关键取舍

- **图**：顺序主干，不并行、不 Supervisor；只有“是否有 red”“是否 approve”两个条件边。
- **HITL**：真 `interrupt()`，不是 `interrupt_before`；审批前只允许纯读取/pending 元数据；超时 `unreviewed_red_risk`。
- **规则/LLM**：规则作用域为“合同级事实 + 条款级证据”，避免“每条规则×每个条款”的噪音；LLM schema 禁止 `risk_level`；LLM 只做 17 字段抽取与解释。
- **异常**：规则异常 → 系统 red（进 HITL），不静默 pass；抽取失败 → 字段 null + degraded；解释失败 → 规则理由兜底。
- **持久化**：SQLite 单文件，零外部服务；测试内存；无 Postgres/Redis。
- **解析**：pypdf 只支持文本型 PDF；扫描件明确不支持；DOCX 无真实分页，统一 p1。

### 9.2 决策与理由

| 决策 | 理由 | 备选/否决 |
|---|---|---|
| 先做“无 LLM 的 4 节点主干” | 先证明环境、图编译、节点契约、规则与报告链路；LLM 失败不会掩盖基础问题 | 直接做 LLM 抽取：调试成本高、无 Key 时不可验证 |
| 规则引擎先实现完整 DSL + 5 条规则 | 等级必须来自规则；先用确定性文本规则验证证据偏移与 fail-closed | 只写 2–3 条硬编码规则：无法验证组合条件与系统 red |
| `segment` 先用空行分段，标题识别留到下步 | 切分是最易错环节，先用 fixture 固定偏移契约，再加复杂算法 | 直接上中英文标题正则：无 fixture 时难定位错误 |
| 证据由条件命中区间直接回填 | 与 ADR-005 的全局坐标一致，避免再做模糊匹配 | 先匹配文本再搜索：同词多次出现时偏移不可靠 |
| 失败不抛异常，写 `status/errors` | 满足“异常必须降级”；图仍能产出失败报告 | 直接抛异常：API/UI 需各自兜底，容易 500 |
| 规则加载失败直接抛异常 | 配置错误必须启动期暴露，不允许零规则出报告 | 跳过坏规则：会静默漏红风险 |
| `pyyaml` 提升为直接依赖 | 代码直接 `import yaml`；不能依赖 langchain 传递依赖 | 使用 JSON：ADR-003 已定 YAML，可读性更好 |

### 10.2 决策与理由

| 决策 | 理由 | 备选/否决 |
|---|---|---|
| PDF 用 pypdf、DOCX 用 python-docx | 纯 Python、BSD/MIT 许可；文本型合同足够 | PyMuPDF（AGPL/商业双许可）；pdfplumber（表格强但慢，未到需要时） |
| canonical text = 页文本 `\n\n` 连接 | 三格式统一坐标系；页间分隔符不属于任何页，定位到分隔符归前一页 | 保存 PDF 字节偏移（映射不稳定）；页内独立偏移（跨页难定位） |
| 扫描件判定为“总文本 < 50 字符” | 简单、可解释；假阳性/假阴性都进入明确报错而非静默 pass | 用图像检测/OCR：超出 MVP |
| DOCX 按 body 顺序读段落与表格 | 避免“先段落再表格”打乱原文；表格行用竖线分隔单元格 | 只读 `document.paragraphs`：会丢表格内容 |
| DOCX 统一 p1 | DOCX 无真实分页，伪造页码会误导 | 强行分页：不诚实且不稳定 |
| 标题识别 + 段落 fallback，不用 LLM | 切分必须可回归；标题格式覆盖大多数合同 | LLM 切分：不确定、偏移不可靠 |
| 数字编号标题加三重约束（短行/非句末标点/≤6 词） | 防止“30 days after...” 被当标题 | 只匹配 `^\d+`：误判率高 |
| 小条款 < 80 字符合并到前一条款 | 避免“只有标题没有内容”的碎片 | 不合并：条款数爆炸、LLM 抽取无上下文 |
| 超长条款 > 4000 字符拆分并加 `-1` 后缀 | 控制单次 LLM 上下文；保留可追溯 id | 不拆：抽取/解释超长、截断丢信息 |
| 条款数 > 200 直接失败 | 避免静默截断导致漏审 | 截断保留前 200：会漏掉尾部条款 |
| 文件头校验（`%PDF-` / `PK`） | 防止改扩展名绕过解析器 | 只信扩展名：误报与异常堆栈不可控 |

### 11.2 决策与理由

| 决策 | 理由 | 备选/否决 |
|---|---|---|
| LLM 调用全部收口到 `call_structured` | 修复重试、类型校验、异常降级只写一遍；节点只依赖 `StructuredLLM` 协议 | 各节点各写一次调用：重试/降级逻辑会漂移 |
| 抽取使用显式 17 字段 schema | Pydantic `extra="forbid"` 从结构上禁止 `risk_level/confidence`，不是靠 prompt 约束 | 自由 dict：字段漂移、幻觉字段无法校验 |
| 按条款串行、单条款失败隔离 | 单点超时不拖垮整份合同；失败条款进 `degraded_steps` + `to_verify` | 批量一次调用：一处失败整批丢 |
| `extraction_status="ok"` 要求**全量**条款成功 | 把“没抽取到”和“合同没约定”分开；部分覆盖时字段规则跳过而不是误报缺失 | 部分成功也算 ok：会产生“合同缺少交付期限”的假阳性 |
| 字段规则新增 `skipped` 语义 | 抽取不可用时既不算 pass 也不报 yellow，评测可单独统计跳过率 | 缺字段 → yellow（ADR 原草案）：无法区分系统降级与真实缺失 |
| 引文只允许精确 + NFC/空白规范化 | 宁可丢字段也不伪造偏移；证据必须可回到原文 | 模糊匹配/标点删除：会制造不可追溯的“证据” |
| 数值含单位/币种残留时保留数字并 `to_verify` | 不静默改写成“正确金额”；币种不自动换算 | 自动剥离单位后当可信值：错币种会被掩盖 |
| 一致性检查只提示不修正 | 金额/币种/日期冲突属于业务判断，规则不应代替人 | 自动按汇率换算：引入不可解释的假设 |
| 合同文本放入 `<untrusted_contract>` 并转义 | 合同是不可信数据；LLM 无工具，输出仍需 schema + 引文校验 | 裸拼接 prompt：可被“忽略以上指令”类文本劫持 |
| 无 Key 时降级而不是报错 | 规则文本匹配仍可交付；报告显式写 limitation | 直接失败：本地演示/评测无法运行 |

### 11.5 对后续的影响

- `facts` 是规则引擎唯一可信的字段来源；后续新增字段规则只需在 `definitions.yaml` 声明 `requires_extraction: true`；
- `locate_quote` 是抽取/解释/证据共享的实现，解释 Quality Gate 可直接复用；
- `extraction_status` 会成为报告与 UI 的一等状态：`ok / degraded / skipped` 必须显示，不能只在日志里提；
- HITL 触发条件只依赖规则等级（red），与抽取状态无关；抽取降级不会绕过人工确认；
- 解释节点应复用 `call_structured` 与 `StructuredOutputError` 的降级路径，避免出现第二套重试逻辑。
