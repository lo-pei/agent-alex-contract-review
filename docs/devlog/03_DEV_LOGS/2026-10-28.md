### 19.6 第 5 条：为什么会出现“快捷填入账号密码”

浏览器与密码管理器（Edge/Chrome、1Password、Bitwarden）会把“`<form>` 里有一个 `type=password` 输入”当成登录表单。API 配置弹窗正好是“一个表单 + 一个 password 输入”，于是点进去就弹“使用已保存的账号密码”。修复：

```html
<form id="llm-form" autocomplete="off">
  <input id="llm-key" name="llm_api_key" type="password"
         autocomplete="new-password" data-lpignore="true" data-form-type="other" />
```

- `autocomplete="new-password"` 是**关键**：浏览器据此认为这是“设置新密码”，不会列出已保存的凭据，也不会提示保存；
- `name` 用 `llm_api_key` 而不是 `password`，避免启发式识别；
- `data-lpignore="true"`（1Password）/ `data-form-type="other"`（部分 Chromium 扩展）抑制第三方密码管理器；
- 厂商、地址、模型输入也加 `autocomplete="off"`，防止邮箱/地址自动填充。
- 测试 `test_llm_form_does_not_trigger_password_autofill` 只检查 `#llm-form` 这一段，不误伤登录弹窗（登录必须保留密码自动填充）。

### 19.7 第 6 条：个人账户弹窗

- **入口**：侧栏账号区改成 `.account-row`（左“退出登录”、右 26px 圆形头像）；无头像时显示昵称/邮箱首字母，有头像显示 `<img>`。
- **弹窗 `#account-dialog`**：
  - 资料：62px 大头像（点击选图）+ “更换 / 移除” + 昵称（≤40）+ 只读邮箱 + “保存资料”；
  - 系统设置：**减少动效**（`data-motion="off"`，全局把 transition/animation 压到 0.001ms）、**自动聚焦输入框**（首屏渲染后聚焦审查重点，但弹窗打开时不抢焦点）；
  - 数据：**清除本机缓存**（只删 `alex.prefs` / `alex.draft`）、**清空审查记录**（逐条 `DELETE /api/reviews/{id}`）。
- **二次确认**：两个按钮都不直接执行，先在下方展开红色 `.account-confirm` 条，写明“将删除账号下 N 条…不可恢复”，再点“确认清除”才跑；点“取消”或关闭弹窗都会复位。清空记录会先 `GET /api/reviews?limit=500` 拿数量，0 条时直接提示“不需要清除”。
- **头像链路**：`squareThumbnail(file, 128)` 用 canvas 居中裁正方形、填白底、导出 `image/jpeg` 0.85，得到约 5–15 KB 的 data URL → `PATCH /api/auth/profile`；服务端 `AVATAR_RE` 只收 `data:image/(png|jpeg|webp|gif);base64,`，上限 400k 字符；`avatar=""` 表示移除。前端先拦 PNG/JPG/WebP 与 5 MB。
- **老库升级**：`users` 表新增 `avatar` 列，用 `_ensure_user_columns()`（`PRAGMA table_info` → `ALTER TABLE`）平滑迁移；`_user_from_row` 对缺列的老 row 也容错。

### 19.9 取舍与已知边界

- 头像存 data URL 而不是文件：单机 SQLite 场景省掉静态目录与清理逻辑；代价是每条 `GET /api/auth/me` 都会带这串（128px JPEG 约 10 KB，可接受），且服务端不做二次编码（只校验前缀与长度）。
- 系统设置只做**本机偏好**，不同步到账号：目前没有“用户设置”表，且这两项本质是浏览器体验，写库收益低。
- 清空审查记录是前端逐条删：后端没有批量接口，20 条以内可接受；后续若放开分页，需要加 `DELETE /api/reviews?all=1` 或后台任务（已记 ISSUE-022）。
- 没有“改密码 / 注销账号”：口令哈希没有版本化迁移路径，先不做（ISSUE-025）。
